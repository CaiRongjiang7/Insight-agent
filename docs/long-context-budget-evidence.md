# 代码探索上下文预算的研究依据

> 核对日期：2026-10-27（Asia/Shanghai）。本次将论证目标明确为“当前模型在长上下文中仍可能受干扰，因此需要控制输入”；保留 2026 年研究及其边界，2023–2025 年研究作为历史背景。以下不是本项目模型的实测；本次不修改预算、模型、代码或部署。当前实现见[架构文档](architecture.md)与[证据台账](evidence-context-ledger.md)。

## 1. 可以成立的结论

**本项目需要的依据是：当前长上下文模型在材料过长、无关或相似干扰较多时，仍可能遗漏关键证据或降低推理质量，因此有必要筛选、组织和控制输入，避免无限制地将飞书会话和仓库代码全部交给模型解析。** 2026 年的 Classifier 和 Mastra 等研究已提供这种“仍可能受干扰”的行为证据；不需要额外证明所有模型都会退化，也不需要先找到某个统一的 Token 失效阈值，才能采用上下文管理。

这里口语上的“注意力发散”，正式表述为“长上下文干扰或关键证据利用下降”，不声明已测得某种内部注意力机制。标称窗口说明可接收的长度，不等于能够稳定利用所有材料。模型、模式与任务差异不否定控制输入的工程动机；它们意味着具体预算应结合证据覆盖、质量、成本与延迟调整，不能只追求更短，也不能把某篇论文的长度直接当作项目上限。下文的数字是实验条件和结果，不是本项目寻找通用失效阈值的目标。

## 2. 2026 年近期证据与适用边界

以下论文均引用固定预印本版本；Mastra 是企业技术报告。发表或更新较新不等于已经过同行评审，也不等于评测了 10 月的全部前沿模型。

### 2.1 10 月新模型：证据结构与长度都影响难度

[Beyond Context Length / LURCH](https://arxiv.org/html/2610.22067v1)，2026-10-15。§5.1 实测 GPT-5.6 Luna、Gemini 3.8 Flash、Qwen3.8-27B 与 Qwen3.5-4B；6,550 题、17 个来源，32K–256K 自然上下文，每题采样三次。

控制长度、任务和模型等变量后，证据覆盖范围、分散程度与推理深度仍与分数相关。Table 1 的分散程度四分位对照为 −1.10 个百分点，不应夸大成普遍大幅崩溃；分模型结果也存在异质性。作者明确这是条件关联，非同一问题加噪声的因果实验，更不是注意力权重实测。工程意义是组织跨文件证据及行为链，不能仅按字符数衡量输入难度。

### 2.2 10 月报告中的反例：同一模型的思考模式很重要

[Mastra: Decision Models Get Context Rot Too](https://mastra.ai/research/decision-models-context-rot)，页面日期 2026-10-22。400 道问题，最多约 26K tokens 的填充；表中“本来能完成的五类任务”子集：GPT-6 Luna 不思考由 93% 降至 79%，思考模式为 95%→94%，后者未显著下降；Gemini 3.8 Flash 为 96%→96%。这些子集数字不是全部 400 题均分。

这是新模型仍会受干扰、同时也能抵抗干扰的直接对照；不能据此断言所有新模型退化。测试未到百万长度，较简单任务、单题采样等也限制外推。26K tokens 与本项目 24,000 字符不是同一计量，更不能拿来证明现有上限。

### 2.3 9 月代码 Agent：适度压缩有成本价值，过度压缩会伤质量

[CliffCompaction](https://arxiv.org/html/2609.26779v1)，2026-09-22，CMU/Bosch。Table 2 的 Kimi K2.6 / Terminal-Bench 2.0：完整上下文解决率 59.16%、平均每题 $0.40；16K 原文压缩为 61.42% / $0.19；8K 则为 50.00% / $0.25。Table 3 的 SWE-bench Verified：完整 73.87%，32K 73.27%，8K 67.60%。

这些是 Agent 执行与压缩策略对照，不能把分数差解释为同一提示词加噪声的纯长度效应，或已证明注意力机制。它更直接支持针对代码任务寻找成本与覆盖的平衡；16K 不是可移植的最优预算，本项目也没有实现该压缩算法。

### 2.4 8 月反证：保留信号后，较强模型缩短输入未显著受益

[Distractor-Aware Truncation](https://arxiv.org/html/2608.03297v1)，arXiv 首次提交 2026-08-04，正文署 08-24，日期存在差异。实际模型含 Haiku 4.5、Sonnet 4.6、Opus 4.7、GPT-5.5（2026-04-23）。对相同样本保留 100%/75%/50%/25% 上下文，比较直接截中间与保留任务信号的删除。

Table 2 的 BABILong（每模型 240 样本），保信号后缩至 25%：Haiku、Sonnet 分别增加 8.3、10.4 个百分点；Opus、GPT-5.5 增加 0.8、1.7 个百分点，均不显著。不能把后两者称作数学意义的满分“天花板”，也不能说短输入总更好。实验是合成任务、未到 1M，保信号依赖已知答案结构；现实检索并无这种保证。盲目截断丢失答案与长度干扰必须区分。

### 2.5 百万附近的控制实验仍有退化，但任务与模型受限

[Classifier Context Rot](https://arxiv.org/html/2605.12366v1)，2026-05-12。§3.1 模型为 Opus 4.6、Gemini 3.1 Pro、GPT 5.4 Thinking，不是 10 月模型全集。Fig.1–2 中 thinking Opus 4.6 对同批攻击材料，添加 800K 良性前缀后召回率从 98.6% 降至 88%；明显攻击所在记录从 100K 增至 800K 时，99.7%→69%。

这是监控分类任务的受控行为证据，不是事故复盘或完整代码修复；未使用推荐的 adaptive thinking，且有校准与数据覆盖限制。没有测量 attention 张量，不能据此声称已经查明内部机制，也不能把下降幅度外推至当前项目模型。

## 3. 2023–2025 年的历史机制背景

以下保留用于理解研究脉络，不作为证明 2026 年当前模型能力的主要证据。

### A. 位置变化可以改变答案质量

[Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/html/2307.03172v3)，2023 年预印本、TACL 2024。

Appendix G.2 / Table 6：同为 20 文档问答，GPT-3.5-Turbo 的答案文档在第 1、10、20 位时，准确率分别为 75.8%、53.8%、63.2%。这支持位置敏感的行为结论；实验模型较旧，也未直接测量注意力熵。

### B. 有直接注意力观察和干预的证据

[Found in the middle: Calibrating Positional Attention Bias Improves Long Context Utilization](https://aclanthology.org/2024.findings-acl.890/)，ACL Findings 2024；[正式 PDF](https://aclanthology.org/2024.findings-acl.890.pdf)。

§2.1 / Figure 4：Vicuna-7B-v1.5-16K 的 20 文档问答分析中，实际统计的平均 self-attention 呈首尾高、中间低，随机重排文档后仍在。分析样本包括答案在中间时答错的案例，不能视为所有输入的统计。Appendix B / Table 5 中，Vicuna 在 NaturalQuestions 的 20 文档中间位置，校准注意力后由 47.34% 提升至 56.19%。权重观察本身不等于因果证明；干预提供更强支持，仍限于所测模型与任务。

### C. 百万窗口模型也可能在较短输入上退化

[NoLiMa: Long-Context Evaluation Beyond Literal Matching](https://arxiv.org/html/2502.05167v3)，ICML 2025，固定引用 2025-07-09 的 v3。

该任务降低问题与证据的字面重合，要求关联检索。Appendix E / Table 10：标称 1M 的 GPT-4.1，短上下文基线 97.0%，32K 为 79.8%，128K 为 64.7%。短基线按论文定义，不是 1K 列，也不是一般代码任务准确率。其“有效长度”依赖基准阈值，不能当作模型硬上限或项目最优预算。

### D. 无关背景与相似干扰项的控制实验

[Context Rot: How Increasing Input Tokens Impacts LLM Performance](https://www.trychroma.com/research/context-rot)，Chroma 技术报告，2025-07-14。

报告覆盖 18 个模型，不是每个子实验都包含全部模型。“Impact of Distractors”固定问题与正确事实，比较无、单个及四个相似干扰项，发现单个即降低表现、更多干扰进一步加重。“LongMemEval”对照 306 题，相关输入平均约 300 tokens，完整输入约 113K；所测模型均在相关输入上更好。相关输入利用标注与人工整理，接近理想检索，不能把差异当成本项目实际检索收益；报告未直接测量退化的全部内部机制，且是企业技术报告。

### E. 代码修复中的对应现象

[LongCodeBench: Evaluating Coding LLMs at 1M Context Windows](https://arxiv.org/html/2505.07897v1)，2025-05-12 预印本。

§3.3：修复输入保留真实修复文件并加入随机仓库文件。Table 3 的 Gemini 2.5 Pro 在 LongSWE-Bench 的 32K、1M 档解决率为 23%、7%。Table 2 显示各档是不同的 100 个案例，仓库也不同，不能将差值视为同一问题纯加噪声的因果效应。代码问答也有随长度提高的模型结果，不能归纳为所有任务越长越差。

### F. 保留与“一定退化”相反的结果

[RULER](https://arxiv.org/html/2404.06654v3)，COLM 2024，Table 3：13 任务均分中，Qwen2-72B 的 4K→128K 为 96.9→53.7，Gemini-1.5-Pro 则为 96.7→94.4。差异说明模型和任务都重要；基准所定义的有效长度不能充当通用安全线。

## 4. 对当前项目的含义

以下为工程推论，尚无本项目消融结果：

- 先用 AST/符号、调用和异常栈定位相关方法，再把必要原文交给模型，减少让模型同时在大量代码中搜索和解释的负担。
- 去除重复日志和无关代码；相似方法、旧版本实现和人的猜测也应区分来源与时间，不能只以关键词相似作为相关性依据。
- 预算须同时考虑关键证据覆盖。异常捕获、状态转换、重连调度、重新注册、业务影响应分别核对，截断可能损失的反证和未知也要保留。
- 按缺口补取方法比盲目加入整个目录更可控；长窗口仍可用于确有必要的长依赖链，不能为了短而删掉关键证据。

当前 24,000/6,000 是选中证据总正文/单条正文的字符限制，不是 Token 数，也不是论文证明的最优值。默认两跳、文件/区域限制同样是实现起点；论文不能证明本项目当前模型已发生相同比例退化，更不能证明预算改动已提高多少准确率。预算耗尽与证据充分必须分开判断；对确有必要的跨文件链路，扩大输入可能比继续压缩更合适，但需先评估，本次未改变任何运行限制。

## 5. 本项目可做的低成本验证（尚未执行）

固定事故、关键证据、模型版本、提示词与生成设置，再分别改变：

1. 只增加无关代码或重复日志，保持关键证据不变。
2. 加入词面相近但用途不同的方法，测量干扰。
3. 在相同总长度下，将关键证据放到首部、中部、尾部。
4. 对照相关方法包、现有选择器与更大范围输入，并记录关键证据遗漏。
5. 在提供商支持时分别评估当前非思考配置与思考模式，同时记录费用和延迟；不能假设换模式无成本或一定改善。

测量关键方法/事实覆盖、结论支持度、引文有效性、未知保留、人工修改量，以及实际输入 Token、延迟与费用；有随机性时重复生成。结合质量、成本和证据覆盖选预算，不能只追求最短输入。论文结果与项目结果分开报告。

## 6. 可用于设计说明或面试的表述

> 即使模型支持很长的上下文，大量无关或相似材料仍可能干扰其对关键证据的利用。因此，项目通过相关性检索、AST 方法定位、去重、有限补取和输入预算，有选择地组织飞书会话与源码上下文，优先保留关键行为链和可追溯引用，避免无界堆积材料。上下文控制的必要性与具体预算如何调优分开论证，参数再结合实际案例的覆盖、质量和成本调整。
